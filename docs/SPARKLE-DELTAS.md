# Sparkle delta updates

> v1.7 feature (Phase 12.4). Smaller patch downloads.

When the user is on Grau 1.6.0 and 1.6.1 ships, the Sparkle
framework inside Grau 1.6.0 can download a *delta* file — just
the diff between the two `.app` bundles — instead of the full
1.6.1 DMG. The full DMG is still used for new installs; the
delta is only used for in-place updates.

## How deltas work in Sparkle 2.x

Sparkle's `generate_appcast` tool (in
`SourcePackages/artifacts/sparkle/Sparkle/bin/generate_appcast`
after the first `xcodebuild` resolves the package) is what
emits the appcast XML. When invoked on a directory of DMGs, it
walks them in version order and produces an
`<enclosure ... sparkle:deltaFrom="..."/>` entry for each
consecutive pair, where `deltaFrom` references the previous
version's file name. The Sparkle framework in the running app
sees that attribute and downloads the delta instead of the
full DMG.

The delta is generated by `generate_appcast` itself (it
embeds `bspatch`/`bsdiff` semantics). No extra toolchain is
needed on the maintainer side.

## Producing a delta-capable appcast

The new `make-appcast.sh` (v1.7) accepts either a single DMG
(legacy, no deltas) or a directory of DMGs (deltas auto).

```
# 1. Stage every release DMG you want to ship in one folder.
mkdir -p dist/dmgs
cp dist/Grau-1.6.0.dmg dist/dmgs/
cp dist/Grau-1.6.1.dmg dist/dmgs/
cp dist/Grau-1.7.0.dmg dist/dmgs/

# 2. Generate the appcast (Sparkle sorts by version, then
#    emits delta-from entries for each pair).
./scripts/make-appcast.sh dist/dmgs/ release

# → dist/appcast.xml
# Items: 3, delta updates: 2
```

The script reports `Items` and `delta updates` counts at the
end so the maintainer can sanity-check before pushing.

## Hosting

`dist/appcast.xml` is the same file Sparkle already consumes
from `https://lucianodiisouza.github.io/grau/appcast.xml`. The
`<sparkle:deltaFrom>` references inside the file are
*relative* to the base URL of the feed, so the corresponding
`.delta` files must sit next to the `.dmg` on the same host.
The v1.7 release process uploads the full `dist/dmgs/` folder
to GitHub Pages (or whatever hosts the feed) so every DMG and
its generated deltas are reachable.

## Pushing the new appcast

```
# After the maintainer reviews the diff and verifies
# "Items: N, delta updates: N-1":
git add dist/appcast.xml
git commit -m "chore(sparkle): appcast with deltas for v1.7.0"
git push
# (The .delta files themselves live on the static host, not in
# this repo — they are generated artifacts.)
```

## Limitations

- **Sign with the same key.** Every DMG and delta must be
  signed with the same EdDSA private key (the one whose
  public counterpart is in `Info.plist` as `SUPublicEDKey`).
  `generate_appcast` does this for you; just keep the same
  `--ed-key-file` across runs.
- **DMG format must be stable.** Delta computation depends on
  the *contents* of the app bundle, not the DMG. Don't shuffle
  the contents between releases.
- **No deltas for major-version upgrades.** Sparkle only
  generates deltas between adjacent versions. 1.6.0 → 1.7.0
  gets a delta; 1.5.0 → 1.7.0 does not (it downloads the full
  1.7.0 DMG). This is by design and is what the user wants
  for major jumps.

## Verifying

The `MANUAL-TEST.md` Phase 12 entry has the full check.
Short version:

1. Install Grau 1.6.0.
2. Publish a 1.6.1 with deltas enabled.
3. From inside Grau 1.6.0, choose **Check for Updates…**.
4. The progress bar should download a file significantly
   smaller than the full DMG (Sparkle shows the size
   before downloading).
5. After the update, the app is on 1.6.1.

If the delta download fails Sparkle automatically retries
with the full DMG, so a broken delta can never brick an
update.
